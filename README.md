# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 排水泵坑水位空态与仲裁规则

排水模块领域化在 `frontend/src/api/drainage-service.ts`，遥测数据在 `src/data/drainage-*.ts`：

- **空值与 0 严格分离**：判读水位为 `number | null`。液位计取不到数 → `null`，列表与详情显示「暂无」并附原因，
  绝不按 0 米参与启泵/正常判定（缺测时启泵也会被挡下）；现场实测可合法录入 0（干涸），两者不同色不同标签。
- **越界单独提示**：启泵水位 > 集水坑容积、读数为负或超容积上限，标「配置越界/读数越界」，不淹没缺测提示。
- **重试与挂账阈值**：每行与详情都有「重试取数」；连续失败 1~2 次只提示可继续重试，第 3 次起提示去现场核对，
  并把液位计按编号挂入设备侧「待校准台账」。同一液位计/泵坑重复上报只记一条。
- **两路取值仲裁**：液位计自动值与现场实测值差 > 0.3m 即冲突，**一律以现场实测为准**（直接量优先于可能漂移的
  间接量），液位计值留档标「未采信」，清单、判读结论、台账全部按实测值回算；现场校准后两路读数一致并销项。
- **存量迁移**：上线前台账按月份分批迁移，页面有批次面板。早年 0 值识别规则：`水位=0` 且无干涸巡检背书
  （巡检日期缺失或当月存在启泵记录）判为疑似断线补 0，迁移前即按缺测处理，迁移时剔除为缺测、挂待校准并在
  备注写明出处；有巡检干涸确认的 0 原样保留；出处不可考的留空待人工补录。
- **归属控制**：会话带归属单位（顶栏可切换演示），非归属单位的重试/实测/校准/泵控操作一律拦截；月份迁移属
  平台批处理，不做单位限制。
- **同源更新**：清单、遥测、设备台账、待校准台账在 service 的单一提交点同步落库（`commit()`），两处入口读数
  一致。规则测试见 `src/api/drainage.test.ts`（`npm test`）。
